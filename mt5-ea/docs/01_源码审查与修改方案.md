# SessionCloseEntry v1.18 源码审查与 v1.19 修改方案

审查对象：`01_当前生产版本_v1.18/SessionCloseEntry.mq5`（MD5 `6951af7fb3e0679a9b0b4ce768ccd8b5`，2941 行，与交付说明一致）。
审查方式：逐行通读全部源码，并对照交易规则文档、三实例实况参数、v1.13–v1.17 编译日志。

## 1. 现有逻辑结论

### 1.1 执行链路（v1.18）

`OnTimer`（每秒）→ 每个启用且有效的组 `ProcessSlot` → `ProcessEvent` → `RunCheck` → `SendOrder` → 下单后核对。

| 环节 | 现状 | 结论 |
|---|---|---|
| 时间计算 | 目标收盘时间（指定时区）− 提前分钟数 = 检查时刻；美/欧夏令时内置规则；服务器偏移自动推算或手动 | 正确。服务器时区模式下，未来日期按"当前"偏移推算，券商换夏令时后计划时刻会随之移动（规则文档已知悉） |
| 就绪机制 | 检查前 120 秒内 EA 须已连续运行 ≥30 秒且已连接，否则记"已错过" | 正确，是"错过不补单"的核心 |
| 运行连续性 | 多处检查点，停顿超过 `InpMaxTimerGapSec` 即取消就绪 | 正确 |
| 价格判断 | 买入用 Ask、卖出用 Bid；≥ / ≤ 单一阈值或到点直接执行；取得有效报价后**只判断一次** | 正确，但只在 `RunCheck` 开头判断一次，**发单前不再复核价格** |
| 止盈止损 | 固定价格 / 距开仓价价格差；价格差模式发单前按最新报价重算，成交后按实际成交价调整一次 | 正确。固定价格模式发单前不按最新报价重查合法性 |
| 防重复 | 事件编号 `SCE_<Magic>_<组>_<日期>_<HHMM>` 写入终端全局变量，先写"发送中"再下单；写入失败禁止下单；同 Magic 单实例锁；已有持仓/挂单/近期成交则跳过 | 正确、完整 |
| 下单后 | 核对持仓 → 核对/补设止盈止损 → 失败按设置平仓并核对 | 正确 |

### 1.2 纳指实例挂在 XAUUSD 图表上：定时触发是否可靠

**可靠，不存在触发问题。** 依据：

- `OnTick()` 是空函数（源码 2937–2940 行），全部逻辑在 `OnTimer()` 中，由 `EventSetTimer(1)` 每秒驱动，与图表品种是否有报价无关。交付说明里"纳指实例的 OnTick 由黄金报价驱动"这句话对本 EA 没有实际影响。
- 报价通过 `SymbolInfoTick(参数里的品种)` 读取，并且每次检查前 `SymbolSelect(sym,true)` 确保品种在"市场报价"中，不依赖图表品种。
- 交易时段、手数规格、保证金全部按参数里的品种查询。

实际存在的只是**显示层面的混淆风险**：XAUUSD 图表上显示的是纳指任务面板，人看图时容易误判。v1.19 增加一条启动日志和面板提示（仅提示，不改行为）。是否把该实例挪到纳指图表由你决定，本次不动。

### 1.3 v1.18 能否独立编译；MQ5 ↔ EX5 能否验证

- **独立编译**：源码只有一条 `#include <Trade\Trade.mqh>`（MT5 标准库），无自定义 mqh、无 DLL、无资源。静态检查未发现语法或类型问题；v1.13–v1.17 的编译日志均为 0 错误 0 警告，v1.18 相对 v1.17 只改了显示函数。结论：**应可独立编译，但本次开发环境是 Linux 云容器，没有 MetaEditor（下载被网络策略拦截），未做真实编译**。
- **MQ5 ↔ EX5 对应**：EX5 文件内含明文版本号。实测 6 个 EX5 各自只包含自己的版本号（当前生产 EX5 含 `1.18`）。这比"仅凭时间戳"多了一条证据：**生产 EX5 确由 `#property version "1.18"` 的源码编译**。但同一版本号下的源码是否逐字节一致，EX5 无法反查；严格验证只能在 Windows 上重新编译后比对大小和行为。状态：**版本号已验证，逐行一致性未验证**。

### 1.4 审查中发现的问题（v1.18 既有）

| # | 问题 | 影响 | v1.19 处理 |
|---|---|---|---|
| A | 价格条件只在检查开头判断一次，之后经过本地检查、服务器预检、写记录才发单，其间价格可能已变 | 可能在条件已不满足时成交（通常毫秒级，预检卡顿时更长） | 发单前按最新报价复核，不满足即不下单 |
| B | 没有点差限制 | 收盘前点差放大时照常成交（规则文档记录黄金收盘前点差可放大约 4 倍） | 新增每组最大允许点差 |
| C | 固定价格模式发单前不按最新报价重查止盈止损合法性 | 极端情况下由券商拒单（不会裸单） | 发单前统一重查 |
| D | 持仓/挂单、交易权限只在检查早期查一次 | 间隔很短，风险低 | 发单前统一复核 |
| E | 头部注释第 5–6 行"未经编译/未测试"与事实不符 | 误导 | 更正注释 |
| F | 事件编号不含价格/方向：**同一组、同一日期、同一收盘时间只能执行一次**。在已处理过的组上改条件但不改日期/时间，任务不会再执行 | 属防重复设计，不是缺陷，但容易踩 | 不改（保持防重复），在参数说明中明确 |
| G | 面板不显示未执行原因，只能翻日志 | 可读性 | 面板增加"本次结果"行 |

### 1.5 实况参数核对（以"当前挂载图表快照_20261111"为准）

- 三个实例均为 `InpRunMode=1`（允许交易）、`InpDemoOnly=false`（真实账户可下单）。
- 已启用的组全部是**日期已过**的一次性任务（A50 S2=11.04；纳指 S1=10.28、S3=11.05；黄金 S1=10.28）。这些任务不会再触发：事件记录在则直接跳过；即使记录丢失，也会因"检查时刻已过"记为"已错过"，不下单。
- `p_*.set` / `cur_*.set` 按交付说明不采用。
- **本次升级不改任何 Magic 和启用状态。**

## 2. v1.19 修改方案

原则：新参数默认值 = 旧行为；现有参数名、枚举值、事件编号格式、全局变量名、日志文件名全部不变；旧 `.set` 加载后效果不变。

| 需求 | 实现 |
|---|---|
| 双边价格区间 | 开仓条件新增选项 `4 = 价格区间`；每组新增 `Sx_RangeLow` / `Sx_RangeHigh`。买入用 Ask、卖出用 Bid，须同时满足 最低价 ≤ 价格 ≤ 最高价。原 ≥ / ≤ / 到点直接执行保留 |
| 美元止盈止损 | 止盈止损模式新增选项 `2 = 账户货币金额`；每组新增 `Sx_TPMoney` / `Sx_SLMoney`。用 `OrderCalcProfit` 按品种、手数、方向换算成价格距离，再用 `OrderCalcProfit` 反算验证，误差超限则不下单。成交后按实际成交价重新定位并记录核算金额。原两种模式保留 |
| 最大允许点差 | 每组新增 `Sx_MaxSpread`（价格单位，Ask−Bid；0 = 不限制）。检查时和发单前各查一次，超限不下单并记录 |
| 下单前安全复核 | 在"发送中"记录建立之后、紧邻下单调用之前，重新取最新报价，依次复核：报价有效性、价格条件、点差、止盈止损（重算+合法性）、交易时段与品种交易模式、手数、交易权限、已有持仓/挂单。任何一项不通过即不下单、任务结束、不重试 |
| 日志与状态 | 结果日志统一包含：计划检查时刻、实际检查报价、允许区间/阈值、点差及上限、止盈止损、未执行原因；面板每组增加"本次结果"行和点差上限显示 |

### 潜在冲突与取舍

1. **状态机**：发单前复核失败时"发送中"记录已写入。沿用 v1.13 的既有做法——把状态改写为终态（条件不满足/跳过），不删除记录、不重试。无新状态码，旧记录兼容。
2. **金额模式与成交后调整**：金额模式内部换算为价格距离后，完全复用价格差模式的成交后调整与只读核对流程（v1.14/v1.15），不新增改单路径。
3. **行为变化（仅更严格）**：即使不使用任何新功能，v1.19 也会在发单前多做一次价格/止盈止损/持仓/权限复核。结果只可能是"原本会下的单在条件已变化时不下"，不会出现"原本不下的单变成下"。
4. **未触碰**：时间/时区计算、就绪与连续性机制、事件编号、单实例锁、下单后核对与平仓逻辑、按星期重复模式（保留但不扩展，不新增任何每日自动交易能力）。
5. **文件命名**：新文件 `SessionCloseEntry_v119.mq5`，不覆盖生产 `SessionCloseEntry.mq5/.ex5`。单实例锁按 Magic 生效，同一 Magic 的 v1.18 与 v1.19 无法同时运行，避免重复下单。
