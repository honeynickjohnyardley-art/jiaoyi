# v1.19 测试结果与尚未验证的风险

## 0. 先说结论

| 要求 | 状态 |
|---|---|
| MetaEditor 编译检查 | **未完成。** 开发环境是 Linux 云容器，没有 MetaEditor，MetaQuotes 下载站被网络策略拦截。**没有生成 EX5。** |
| 旧功能回归测试 | 已在离线模拟器中完成：33 个场景，v1.18 与 v1.19 结果逐项一致 |
| 新功能测试 | 已在离线模拟器中完成：42 项断言全部通过 |
| 模拟账户（券商 Demo）验证 | **未完成。** 需要在装有 MT5 的 Windows 机器上执行，步骤见 `05_升级与回滚步骤_WorkBuddy.md` |

所以 v1.19 目前的状态是：**逻辑经过离线模拟验证，尚未经 MetaEditor 编译，也未在任何 MT5 终端运行过。在第 05 号文档的编译与模拟账户验证全部通过之前，不得用于实盘。**

## 1. 离线模拟器是什么、能证明什么

`tests/` 目录下：

- `mq5_to_cpp.py`：把 `.mq5` 源码机械改写成 C++（只改语法外壳，如字符串字面量、动态数组、前置声明；不改任何逻辑）。
- `mql_shim.h`：用 C++ 实现 EA 用到的 MQL5 接口，并模拟一个券商：品种规格、报价、交易时段、持仓、成交历史、终端全局变量、`OrderCalcProfit`、下单/改单/平仓。
- `scenarios.cpp`：测试场景。同一份场景分别与 v1.18、v1.19 源码一起编译运行。
- `run_tests.sh`：一键运行。

能证明的：EA 自身的判断逻辑（时间、条件、复核顺序、状态记录、防重复）在给定输入下的行为；两版源码在 g++ 下都能通过类型检查，且 v1.19 没有比 v1.18 多出任何编译警告。

**不能证明的**：MQL5 编译器是否接受（两种语言有细微差别）；真实券商的合约规格、`OrderCalcProfit` 的实际返回、成交方式、拒单行为；真实终端的定时器与图表对象表现。

## 2. 旧功能回归（v1.18 对比 v1.19）

方法：每个场景结束后输出"结果指纹"——全部事件记录的状态码、EA 发出的每一个交易请求（类型、品种、手数、成交价、止损、止盈、返回码）、最终持仓。两版指纹逐字比较。

## 3. 新功能测试（仅 v1.19）

结果：**42 项全部通过**（明细见 `tests/feature_results.txt`，日志和面板原文样例见 `tests/sample_logs.txt`）。

| 功能 | 覆盖内容 |
|---|---|
| 价格区间 N01–N11 | 区间内成交；低于下限、高于上限不下单；恰好等于上下限满足；买入按 Ask 判断；**检查时在区间内但发单前跌出/涨出区间 → 不下单，价格回来也不补单**；单边条件同样在发单前复核；上下限填反或只填一边 → 参数无效 |
| 金额止盈止损 N12–N21d | 纳指 0.1 手盈利 60/亏损 20 → 距离 600/200，核算 +60.00/−20.00；滑点 2.5 后按实际成交价重新定位，核算仍为 +60/−20；黄金 1 手、A50 最小手数；盈亏两侧换算率不同的非美元品种（止损不超目标）；金额过小、未填、`OrderCalcProfit` 失败、小于券商最小止损距离 → 不下单；改单被拒时保留原保护；成交不带保护时补设，补设失败则平仓 |
| 最大点差 N22–N26 | 超限不下单并记录点差数值；等于上限允许；**检查时合格、发单前扩大 → 不下单**；负数 → 参数无效 |
| 发单前复核 N27–N34 | 检查后出现本 EA 持仓、算法交易被关闭、品种变为只平仓、取不到报价、固定止损价已被击穿 → 均不下单；新功能任务同样只执行一次、错过不补、仅记录信号模式不下单 |
| 日志与面板 N35–N37 | 日志包含检查时刻、检查报价、允许区间、点差及上限、原因；面板包含区间、点差上限、本次结果与原因、金额设定 |
| 图表品种不一致 N38 | 纳指任务挂在 XAUUSD 图表，且黄金完全没有报价 → 仍按时触发并成交 |

## 4. 尚未验证的风险

| # | 风险 | 说明 | 如何消除 |
|---|---|---|---|
| 1 | **MQL5 编译未验证** | C++ 能通过不等于 MQL5 能通过。新增代码只用了 v1.18 已在用的语法和函数，外加一个标准函数 `OrderCalcProfit` 和预定义变量 `_Symbol`，预期可编译，但必须实测 | 第 05 号文档步骤 2 |
| 2 | `OrderCalcProfit` 在该券商各品种上的真实表现 | 模拟器按线性模型计算。真实券商可能对金额取整、对中文名 CFD 品种返回失败等。EA 的处理是：计算失败或反算偏差超限就不下单，所以最坏结果是"不交易"，不是"带错止损交易" | 模拟账户上看启动日志里的"金额换算预览"，与规则文档"1 手 1 价格单位 = 1 美元"核对 |
| 3 | 发单前复核增加的耗时 | 多一次本地查询（含读取成交历史），预计毫秒级。若终端卡顿超过容错窗口，结果是"已错过"，不会延迟下单 | 模拟账户观察日志中检查与成交的时间差 |
| 4 | 止盈止损金额的实际偏差 | 止损滑点、手续费、隔夜利息、点差不在换算内（见参数说明） | 属市场与券商因素，无法由 EA 消除 |
| 5 | 面板行数增加 | 每组可能多 1–2 行；三实例各自图表上显示 | 模拟账户目测 |
| 6 | v1.18 MQ5 ↔ 生产 EX5 逐行一致性 | 只验证到版本号一致（EX5 内含 `1.18`） | 在 Windows 上重新编译 v1.18 到临时目录，比对大小；非本次升级的前置条件 |
| 7 | 按星期重复模式 | 保留未改，回归只覆盖了 2 天 | 你的规则已禁止使用该模式 |
| 8 | 真实行情下"发单前复核"与成交之间仍有极短间隔 | 复核通过后立即调用下单，中间不再有其他耗时操作，但市价单成交价由券商决定，可能落在区间外 | 市价单固有属性；允许滑点参数 `InpDeviationPoints` 对部分账户类型有效 |

## 5. 复现方法

```bash
cd mt5-ea/tests
./run_tests.sh
```

需要 Python 3 和 g++（C++17）。脚本结束码为 0 表示回归一致且新功能断言全部通过。
